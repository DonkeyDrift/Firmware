# 驴车转向值异常分析与保护方案

## 1. 根因分析 (Root Cause Analysis)
通过代码审查，定位到异常值 `S = -182` 的产生原因如下：
- **数据源头**：转向值 `S` 源自 GPIO 36 的 PWM 中断捕获 (`pwm_value[0]`)。
- **计算逻辑**：第 691 行使用了 `map` 函数进行线性映射：
  ```cpp
  car_output.steering = map(rc_data.steering - 1488, 872 - 1488, 2113 - 1488, -100, 100);
  ```
- **缺陷**：`map` 函数不具备边界检查能力。当输入信号受到电磁干扰或接触不良导致 PWM 脉宽读数异常偏小（例如捕获到 0us 或极短的噪声脉冲）时，线性映射公式会计算出远超 `-100` 的负值（如 `-182`）。
- **结论**：系统缺乏对原始信号的有效性校验、平滑滤波及输出限幅保护。

## 2. 实施计划 (Implementation Plan)

### Step 1: 定义数据结构与常量
在 `mus4.ino` 头部添加必要的全局变量和常量，用于滤波和状态管理。
- **常量**：
  - `PWM_VALID_MIN = 500`, `PWM_VALID_MAX = 2500` (原始信号物理有效范围)
  - `MA_WINDOW_SIZE = 5` (滑动平均窗口大小)
  - `MAX_ERROR_COUNT = 3` (连续异常阈值)
- **变量**：
  - `steering_history[MA_WINDOW_SIZE]` (历史数据缓存)
  - `steering_index` (环形缓冲区索引)
  - `last_valid_steering_pwm` (上一次有效值，用于补全)
  - `steering_error_count` (异常计数器)
  - `safe_mode_active` (安全模式标志)

### Step 2: 实现核心处理函数
封装一个新的函数 `process_steering_signal(int raw_pwm)`，实现以下逻辑：
1.  **信号校验**：检查 `raw_pwm` 是否在 `[500, 2500]` 范围内。若无效，使用 `last_valid_steering_pwm` 补全。
2.  **滑动平均**：将有效值推入环形缓冲区，计算平均值，抑制突发跳变。
3.  **映射计算**：执行原有的 `map` 逻辑。
4.  **异常检测**：检查映射后的值是否超出 `[-100, 100]`。
    - 若超限：`steering_error_count++`。若连续 3 次超限，触发安全模式。
    - 若正常：重置 `steering_error_count = 0`。
5.  **硬限幅**：使用 `constrain` 确保最终输出在 `[-100, 100]`。

### Step 3: 修改主循环逻辑
修改 `loop()` 函数中的相关代码：
- **替换**：将第 618 行的直接赋值 `rc_data.steering = pwm_value[CH_STEERING]` 替换为调用处理函数。
- **替换**：将第 691 行的 `map` 计算替换为使用处理后的安全值。
- **安全模式响应**：在检测到安全模式激活时，强制 `car_output.throttle = 0` 并打印告警。

### Step 4: 编写单元测试
添加 `run_steering_tests()` 函数，在 `setup()` 中调用（仅运行一次）。
- **测试用例 1 (正常值)**：输入 1488 (中位)，期望输出 ~0。
- **测试用例 2 (边界值)**：输入 872/2113，期望输出 -100/100。
- **测试用例 3 (噪声注入)**：注入 0 或 3000，验证是否被过滤并保持上一次值。
- **测试用例 4 (连续异常)**：连续注入异常值，验证是否触发安全模式告警。

### Step 5: 验证与交付
- 编译并模拟运行。
- 检查串口输出，确认异常值被过滤，且 `S` 值始终限制在安全范围内。
