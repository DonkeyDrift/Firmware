# CNB 云端编译 + 本地烧录验证闭环 —— 跨项目实施指南（提示词）

> 来源：PhotoPlayer/Tab5Scrub 项目 2026-09 已验证的成熟方案（`.cnb.yml` +
> `tools/cnb_ci.sh` + `tools/bootstrap_esptool.sh`，可直接复制作参考实现）。
> 本文档面向**另一个项目的 AI Agent**，照此搭建即可获得同款全自动闭环。

---

## 0. 你的任务

你是一名嵌入式固件工程师 AI Agent。项目采用「云端编译 + 本地烧录」模式：
完整工具链（如 ESP-IDF）**不装在本地**，编译在腾讯云 CNB（cnb.cool）流水线完成；
烧录与真机验证在本地由你脚本化执行。你的标准职责是维护一条全自动闭环：

**改代码 → commit → push（自动触发云构建）→ 等构建 → 下载产物 → 本地烧录 →
串口验证版本 → 汇报结果**

全程无需人工干预；烧录验证必须以退出码判定（VERIFY PASS/FAIL）。

## 1. 架构总览（三部分）

| 组成 | 载体 | 职责 |
|---|---|---|
| 云端流水线 | 仓库根 `.cnb.yml` | 工具链镜像内编译固件，产物 tar.gz 上传为 commit 附件 |
| 本地闭环脚本 | `tools/cnb_ci.sh` | trigger / wait / download / flash / verify / run 子命令，凭据走 git credential |
| 版本自证链 | 固件内嵌 git describe 版本 + 串口启动日志 | 证明"烧进硬件的确实是本次 commit 的云端产物" |

## 2. 云端流水线 `.cnb.yml`（模板，尖括号为占位符）

```yaml
# 触发：push 自动（路径过滤）/ CNB 网页手动 / API
$:
  push: &fw-pipeline
    - name: firmware
      ifModify:                      # 路径过滤：无关变更不浪费构建资源
        - "<固件目录>/**"
        - ".cnb.yml"
      runner:
        cpus: 8                      # 按工具链需要给足；内存 = cpus × 2GiB
      docker:
        image: <工具链官方镜像，如 espressif/idf:v5.5.1>
        volumes:
          - /cache/ccache:copy-on-write            # 编译缓存（跨构建复用）
          - ./<项目>/<依赖目录>:copy-on-write       # 依赖/组件缓存，避免每次重下
      env:
        CCACHE_DIR: /cache/ccache
      stages:
        - name: check-changes
          script: |
            # 手动触发、新分支总是构建
            case "$CNB_EVENT" in web_trigger*|api_trigger*) exit 0;; esac
            if [ -z "$CNB_BEFORE_SHA" ] || [ "$CNB_BEFORE_SHA" = "0000000000000000000000000000000000000000" ]; then
              exit 0
            fi
            files=$(git diff --name-only "$CNB_BEFORE_SHA" "$CNB_COMMIT" 2>/dev/null) \
              || files=$(git show --pretty= --name-only "$CNB_COMMIT")
            echo "$files" | grep -qE '^(<固件目录>/|\.cnb\.yml$)' || exit 78   # 78=静默跳过
        - name: build
          timeout: 40m               # 首次冷缓存全量编译慢，给足超时
          script: |
            command -v idf.py >/dev/null 2>&1 || . "$IDF_PATH/export.sh"
            cd <项目目录> && <构建命令，如 idf.py build>
        - name: package
          script: |
            cd <项目目录>/build
            tar czf "../../<产物名>_${CNB_COMMIT_SHORT}.tar.gz" \
              <bin 文件列表…> flash_args flasher_args.json
        - name: upload-artifact
          image: cnbcool/attachments:latest
          settings:
            attachments:
              - "./<产物名>_${CNB_COMMIT_SHORT}.tar.gz"
  web_trigger: *fw-pipeline           # YAML 锚点复用同一条流水线
  api_trigger: *fw-pipeline
```

CNB 内置环境变量（脚本直接用）：`CNB_EVENT`（push / web_trigger / api_trigger）、
`CNB_BEFORE_SHA`（新分支为全 0）、`CNB_COMMIT`（完整 sha）、
`CNB_COMMIT_SHORT`（**8 位**短 sha，产物文件名统一用它）。

关键语义：
- **exit 78 = 流水线显示"成功"但实际跳过**。跳过的构建既不上报状态也无产物——
  本地脚本等待前必须先确认本次提交改了受管路径，否则死等超时。
- 三种事件用锚点复用，改一处三处生效。

## 3. 版本自证链（闭环可信的根基）

固件必须做到：**编译期嵌入 `git describe --always --dirty`（或等效），启动时从
串口打印一行 `App version: <值>`**（CMake `execute_process` 生成 version.h，
或构建前生成版本源文件）。云端无 tag 时输出 7 位短 sha；本地有 tag 时是
`v1.0-N-g<7位>[-dirty]`——**本地验证统一只匹配 sha 前 7 位**。

有了它，verify 脚本核对"串口打印的版本包含目标 commit 前 7 位"即可断言：
设备上跑的就是这次提交的云端产物。

## 4. 本地闭环脚本 tools/cnb_ci.sh 的关键实现

### 4.1 凭据：git credential，不落明文

```bash
pw=$(printf "protocol=https\nhost=cnb.cool\nusername=cnb\n\n" | git credential fill \
     | sed -n 's/^password=//p')
```

令牌存 Windows 凭据管理器（首次 push 或 `git credential approve` 写入一次即可）。
API 权限只需 `repo-cnb-detail:r`（查构建状态 + 下载附件），**不需要**
`repo-cnb-history:r`。git push 本身复用同一凭据。

### 4.2 构建状态查询：两条路，别混

| 触发方式 | 查询端点 | 注意 |
|---|---|---|
| push | `GET https://api.cnb.cool/<slug>/-/git/commit-statuses/<sha>` | 构建**结束才**上报；按 `context` 字段过滤目标流水线；同 commit 多条取 `created_at` 最新 |
| api_trigger | `POST /<slug>/-/build/start` body `{"event":"api_trigger","branch":"…"}` 返回 **sn**；`GET /<slug>/-/build/status/<sn>` | **不上报 commit-statuses**；trigger 后把 sn 传给等待逻辑精确匹配，避免同 commit 旧构建误判 |

### 4.3 产物下载：两段跳，签名地址单次有效

1. `GET https://api.cnb.cool/<slug>/-/commit-assets/download/<完整sha>/<文件名>`（Bearer 鉴权）→ 响应 302，取 `Location` 头
2. 直接 curl 该 Location 下载（asset.cnb.cool 签名地址，**无需鉴权**）

**每次重试都必须重新走第 1 步取新 302**（签名 URL 用过即失效）。
文件名中的短 sha 是 **8 位**（CNB_COMMIT_SHORT）。

### 4.4 Python 环境解析链（烧录只需 esptool + pyserial 两个包）

解析顺序：`$IDF_PYTHON` 显式覆盖 → 仓库内轻量 venv（`bootstrap_esptool.sh`
一键创建，仅 `pip install esptool pyserial`，约 25MB，幂等）→ 本机历史工具链
env → 都没有则自动 bootstrap。**烧录/验证完全不依赖完整工具链**，新机器
clone + bootstrap 一次即可工作。

### 4.5 烧录

```bash
python -m esptool --chip <芯片> -b 460800 \
  --before default_reset --after hard_reset -p <COM> write_flash "@flash_args"
```

- 端口自动探测：`serial.tools.list_ports` 按 USB VID 过滤（Espressif = `VID:PID=303A:`），取第一个
- `@flash_args` 用产物自带文件，分区地址零维护

### 4.6 串口验证（纯 pyserial，不依赖任何 MCP/专有工具，任意 Agent 可复现）

```python
s = serial.Serial(); s.port=port; s.baudrate=115200; s.timeout=0.2
s.rts=False; s.dtr=False      # pyserial 默认拉起 RTS/DTR，必须先清零再 open
s.open()
def set_rts(v):
    s.setRTS(v); s.setDTR(s.dtr)   # Windows usbser.sys workaround：setRTS 后重设 DTR 才真正下发
set_rts(True);  time.sleep(0.2)    # EN 拉低复位
set_rts(False)                     # 释放；DTR 恒 False = IO0 高 → 正常启动，不进下载模式
# 读 N 秒日志 → 找含 "App version" 的行 → 核对包含 sha 前 7 位
# → 打印 VERIFY PASS / FAIL，退出码 0 / 1
```

## 5. AI Agent 标准工作流（抄进项目记忆 / AGENTS.md）

1. 编辑代码 → `git commit -m "<type>(<scope>): 中文描述"`（约定式提交）
2. `git push origin <分支>`（可配多 pushurl 一推多远端；push 自动触发云构建）
3. **自检**：本次提交必须改了受管路径（固件目录 / `.cnb.yml`），否则构建被
   check-changes 跳过——无状态无产物，`run` 会死等超时
4. `bash tools/cnb_ci.sh run <commit-sha>` 一条龙：等构建 → 解压产物到
   `tools/.cnb_fw/` → 探测端口烧录 → verify
5. 汇报：构建耗时 / 烧录端口与结果 / verify 结论（App version 行原文 + PASS/FAIL）

## 6. 踩坑清单（全部实测，逐条内化）

1. **被 check-changes 跳过的构建无状态、无产物**——等待前先确认本次提交动了受管路径。
2. **api_trigger 构建不上报 commit-statuses**——只能按 sn 查 `/build/status/<sn>`。
3. **commit-statuses 构建结束才上报**——轮询开头先 sleep 几秒，并容忍 `none`（尚未开始）状态。
4. **asset 签名 URL 单次有效**——每次下载重试都重新取 302。
5. **产物文件名的短 sha 是 8 位**（CNB_COMMIT_SHORT），verify 版本匹配用 7 位，别混。
6. **COM 口被占**：serial MCP / 串口监视器等占用时 esptool 报 PermissionError——烧录前断开一切占用 COM 口的工具。
7. **pyserial 默认拉起 RTS/DTR**——open 前先 `rts=dtr=False`，否则一开串口就把设备打进下载模式。
8. **Windows usbser.sys 的 RTS 传播 bug**——`setRTS` 后必须重设一次 DTR，复位脉冲才真正到达设备（esptool reset.py 同款 workaround）。
9. **本地工具链编译与云端产物可能有行为差异**（镜像/环境差异）——验证一律以云端产物为准，本地编译只做语法/链接检查。
10. **流水线超时要给足**（首次冷缓存全量编译慢）；配 ccache + 依赖目录缓存后增量构建大幅提速。
