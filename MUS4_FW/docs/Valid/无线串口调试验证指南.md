# 无线串口调试验证指南

> **部分章节已被新生命周期覆盖**：本文写于 AP+STA 长期共存阶段，第九章「验证 AP + STA 双模式」与"AP 始终作为保底入口"等描述已被 v1.7.18 起的 **AP/STA 互斥切换**覆盖：STA 上线后 AP 在 1s grace 通过即关闭，STA 失败/断开后 AP 自动恢复。基础无线 OTA、AUTH、Park 锁定、命令权限分层等验证步骤仍然有效。新生命周期细节见 [`docs/Plan/AP_STA互斥切换方案.md`](../Plan/AP_STA互斥切换方案.md) 与 [`docs/Inspect/wifi-ap-sta-lifecycle-inspection.md`](../Inspect/wifi-ap-sta-lifecycle-inspection.md)。

## 结论

无线串口功能在代码层面已经完成，当前主固件 `mus4.ino` 已启用 `ENABLE_WIFI_CONSOLE`，包含以下能力：

- Wi-Fi AP 调试入口：SSID 为 `MUS4-DEBUG`。
- TCP 无线串口：端口 `2323`。
- Web Console：端口 `80`。
- AP + STA 双模式：AP 始终作为保底入口；若编译期配置了 `WIFI_STA_SSID` / `WIFI_STA_PASSWORD`，会同时尝试连接外部路由器。
- 命令认证：使用 `AUTH:<密码>` 解锁受保护命令。**当前 `WIFI_CONSOLE_AP_PASSWORD` 为空：全通道免认证，任何工具发送受保护命令都无需先 AUTH，`AUTH:` 仍可发送并返回 `AUTH_OK`**（见 `docs/Plan/DEV模式影响面与运行逻辑映射.md` §3.2）；下文 `AUTH:mus4-debug`、`NACK:UNAUTHORIZED` 等步骤对应配置了非空密码的场景。
- OTA 窗口：认证且 Park 锁定后，用 `ENABLE_OTA` 临时开启 120 秒 OTA 窗口。

但“完成”只代表代码与桌面策略测试已具备闭环，仍需要按本文步骤完成真机验证后，才能视为硬件环境下验证通过。

- `tests/test_wireless_console_policy.py`：认证、Park 锁定、OTA 窗口、Web/TCP 权限一致性测试。

## 前置条件

1. ESP32 已接入 USB，电脑能识别串口。
2. 已安装 Arduino CLI、ESP32 core 和项目所需库。
3. 已安装 Python 依赖：

```powershell
pip install pyyaml pyserial pytest
```

4. 如果使用 Windows + WSL 高速构建，先检查 WSL 构建环境：

```powershell
.\arduino-cli-wsl.ps1 -Check
```

5. 调试电脑需要有 Wi-Fi，并能连接 `MUS4-DEBUG` 热点。

## 一、先跑桌面策略测试

这些测试不需要连接硬件，用于确认无线串口权限策略没有被破坏。

```powershell
pytest tests/test_wireless_console_policy.py -v
```

预期结果：

```text
所有用例通过，包含：
- 未认证允许 PING / STATUS
- 未认证拒绝控制命令
- 认证后允许控制命令
- TEST / BENCH / REGRESS 等诊断命令要求 Park 锁定
- ENABLE_OTA 要求认证且 Park 锁定
- Web Console 权限与 TCP Console 一致
```

如果失败，先修复策略或同步 `mus4.ino` 与 `wireless_console_policy.py` 的行为，不要直接进入真机验证。

## 二、编译并上传固件

推荐使用 WSL 高速构建：

```powershell
.\arduino-cli-wsl.ps1 -Compile -Upload -Serial
```

如果不用 WSL，使用 Python 工具：

```powershell
python arduino-cli.py -cu --no-progress
python arduino-cli.py -s
```

需要指定串口时：

```powershell
python arduino-cli.py -cu --port COM9 --no-progress
python arduino-cli.py -s --port COM9
```

串口监视器启动后，观察启动日志，预期看到类似内容：

```text
WiFi Console AP: MUS4-DEBUG IP: 192.168.4.1 Port: 2323 Web: 80
System Locked: Park Mode Active
```

如果看到 `WiFi Console AP start failed`，直接查看本文“故障排查”。

## 三、连接 Wi-Fi AP

在电脑 Wi-Fi 列表中连接：

```text
SSID: MUS4-DEBUG
密码: mus4-debug
```

连接后，电脑通常会获得 `192.168.4.x` 地址，ESP32 AP 地址为：

```text
192.168.4.1
```

可用 PowerShell 验证连通性：

```powershell
Test-NetConnection 192.168.4.1 -Port 2323
Test-NetConnection 192.168.4.1 -Port 80
```

预期：`TcpTestSucceeded : True`。

## 四、调试 TCP 无线串口

### 方法 A：使用 PowerShell TcpClient

Windows 默认不一定有 `nc`，推荐直接用 PowerShell 建立 TCP 连接。

```powershell
$client = [System.Net.Sockets.TcpClient]::new("192.168.4.1", 2323)
$stream = $client.GetStream()
$reader = [System.IO.StreamReader]::new($stream)
$writer = [System.IO.StreamWriter]::new($stream)
$writer.NewLine = "`n"
$writer.AutoFlush = $true
$reader.ReadLine()
$reader.ReadLine()
```

预期前两行返回：

```text
MUS4 WiFi Console Ready
Use AUTH:<password> to unlock control commands
```

发送公开命令：

```powershell
$writer.WriteLine("PING")
$reader.ReadLine()
```

预期返回：

```text
PONG
```

查询状态：

```powershell
$writer.WriteLine("STATUS")
$reader.ReadLine()
```

预期返回类似：

```text
STATUS mode=0 park=1 throttle=0 steering=0 wifi_frames=0 wifi_errors=0 ota_window=0 ota_progress=0 ota_ttl_ms=0 version=... web_port=80 ap_ip=192.168.4.1 sta_configured=0 sta_connected=0 sta_ip=0.0.0.0
```

认证：

```powershell
$writer.WriteLine("AUTH:mus4-debug")
$reader.ReadLine()
```

预期返回：

```text
AUTH_OK
```

认证后发送控制命令：

```powershell
$writer.WriteLine("0:0")
$reader.ReadLine()
```

预期返回：

```text
ACK
```

测试未授权保护时，可以重新连接 TCP，然后不认证直接发送：

```powershell
$writer.WriteLine("10:20")
$reader.ReadLine()
```

预期返回：

```text
NACK:UNAUTHORIZED
```

关闭连接：

```powershell
$client.Close()
```

### 方法 B：使用 nc / ncat / PuTTY

如果环境中有 `nc` 或 `ncat`：

```bash
nc 192.168.4.1 2323
```

手动输入：

```text
PING
STATUS
AUTH:mus4-debug
0:0
```

如果使用 PuTTY：

```text
Connection type: Raw
Host Name: 192.168.4.1
Port: 2323
```

## 五、调试 Web Console

连接 `MUS4-DEBUG` 后，在浏览器打开：

```text
http://192.168.4.1/
```

页面应显示 `MUS4 Web Console`，并提供命令输入框、串口式日志窗口、状态栏和动态数据曲线画布。

建议按顺序点击或输入：

```text
PING
STATUS
AUTH:mus4-debug
STATUS
0:0
```

预期：

- 日志窗口追加 `> PING` 和 `PONG`。
- `PING` 返回 `PONG`。
- `STATUS` 返回当前车辆模式、Park、油门、转向、Wi-Fi 统计、OTA 状态和 AP/STA IP。
- `AUTH:mus4-debug` 返回 `AUTH_OK`。
- 认证后 `0:0` 返回 `ACK`。
- 动态曲线画布持续刷新 Throttle、Steering、Current、GyroZ。
- 操作 RC 油门/转向时，Throttle/Steering 曲线应实时变化。
- 转动或晃动设备时，GyroZ 曲线应出现波动。

也可以用 PowerShell 直接调用 Web API：

```powershell
Invoke-RestMethod -Uri "http://192.168.4.1/api/status"
Invoke-RestMethod -Uri "http://192.168.4.1/api/cmd" -Method Post -Body "PING" -ContentType "text/plain"
Invoke-RestMethod -Uri "http://192.168.4.1/api/cmd" -Method Post -Body "AUTH:mus4-debug" -ContentType "text/plain"
Invoke-RestMethod -Uri "http://192.168.4.1/api/log?since=0"
Invoke-RestMethod -Uri "http://192.168.4.1/api/data?since=0"
```

注意：TCP Console 与 Web Console 当前共享 `wifiConsoleAuthenticated` 状态。真机验证时建议分别测试“新连接未认证被拒绝”和“认证后允许命令”。

## 六、验证 Park 锁定保护

诊断命令和 OTA 开窗要求 Park 锁定。

在默认启动状态下，系统会进入 Park 锁定：

```text
park=1
```

认证后发送诊断命令：

```text
TEST
BENCH
REGRESS
FILTER_TEST
```

预期：Park 锁定时允许执行；Park 解锁后返回：

```text
NACK:UNAUTHORIZED
```

如果要验证 Park 解锁状态，需要通过 RC CH3 按键或实际遥控输入切换 Park 状态，然后再次执行 `STATUS` 确认 `park=0`。

## 七、验证 OTA 窗口

OTA 开窗必须满足：

```text
已认证
car_output.park == PARK_LOCKED
```

在 TCP 或 Web Console 中执行：

```text
AUTH:mus4-debug
ENABLE_OTA
```

预期返回：

```text
OTA_READY ip=192.168.4.1 port=3232 ttl_ms=120000
```

查询 OTA 状态：

```text
OTA_STATUS
```

预期返回类似：

```text
OTA_STATUS started=1 window=1 in_progress=0 ttl_ms=... progress=0 park=1
```

关闭 OTA 窗口：

```text
DISABLE_OTA
```

预期返回：

```text
OTA_CLOSED
```

如果超过 120 秒没有上传，USB 串口日志应出现：

```text
WiFi OTA closed: TIMEOUT
```

如果 Park 解锁，OTA 窗口会关闭，USB 串口日志应出现：

```text
WiFi OTA closed: PARK_UNLOCKED
```

## 八、执行无线 OTA 上传

先通过 Console 打开 OTA 窗口：

```text
AUTH:mus4-debug
ENABLE_OTA
```

然后在 120 秒内执行 OTA 上传。具体命令取决于本机 Arduino CLI 对网络端口的识别情况。

先列出开发板：

```powershell
arduino-cli board list
```

如果能看到 `mus4-ota` 或 `192.168.4.1` 对应的网络端口，可尝试：

```powershell
arduino-cli upload -p 192.168.4.1 --fqbn esp32:esp32:esp32 --input-dir build
```

如果 Arduino CLI 网络端口不可用，先只验证 OTA 窗口、状态和关闭逻辑，不要把 OTA 作为无线串口验收的阻塞项。

## 九、验证 AP + STA 双模式

当前代码默认：

```cpp
#define WIFI_STA_SSID ""
#define WIFI_STA_PASSWORD ""
```

因此默认只保证 AP 可用，`STATUS` 中应看到：

```text
sta_configured=0 sta_connected=0 sta_ip=0.0.0.0
```

如需测试 STA，请复制根目录的 `WirelessSecrets.example.h` 为 `WirelessSecrets.h`，并在 `WirelessSecrets.h` 中填写真实 SSID 与密码。`WirelessSecrets.h` 已被 `.gitignore` 忽略，不要把真实 Wi-Fi 密码提交到仓库。

```powershell
Copy-Item .\WirelessSecrets.example.h .\WirelessSecrets.h
```

`WirelessSecrets.h` 示例内容：

```cpp
#pragma once

#define WIFI_STA_SSID "你的路由器SSID"
#define WIFI_STA_PASSWORD "你的路由器密码"
```

STA 连接成功时，USB 串口会输出：

```text
WiFi STA connected IP: <路由器分配的IP>
```

`STATUS` 中应看到：

```text
sta_configured=1 sta_connected=1 sta_ip=<路由器分配的IP>
```

即使 STA 连接失败，AP 仍应保持可用，并可继续通过 `192.168.4.1` 调试。

## 十一、常见问题排查

### 找不到 `MUS4-DEBUG` 热点

1. 确认固件中 `ENABLE_WIFI_CONSOLE` 已定义。
2. 查看 USB 串口是否出现：

```text
WiFi Console AP start failed
```

3. 复位 ESP32 后等待 5 秒以上。
4. 如果反复失败，先断电重启 ESP32，再重新上传固件。

### 能连 Wi-Fi，但 TCP 端口不通

执行：

```powershell
ipconfig
Test-NetConnection 192.168.4.1 -Port 2323
```

检查电脑 Wi-Fi 网卡是否获得 `192.168.4.x` 地址。如果没有，断开重连 `MUS4-DEBUG`。

### Web 页面打不开

先测试端口：

```powershell
Test-NetConnection 192.168.4.1 -Port 80
```

如果 TCP 2323 可用但 80 不可用，检查 USB 串口启动日志是否包含 `Web: 80`。

### 发送控制命令总是 `NACK:UNAUTHORIZED`

先发送：

```text
AUTH:mus4-debug
```

每次新的 TCP 客户端连接都会清除认证状态，需要重新认证。

### `ENABLE_OTA` 返回 `NACK:UNAUTHORIZED`

确认两个条件：

```text
AUTH:mus4-debug 已返回 AUTH_OK
STATUS 中 park=1
```

如果 `park=0`，需要通过 RC CH3 让系统回到 Park 锁定。

### `ENABLE_OTA` 返回 `NACK:PARK_REQUIRED`

说明认证已经通过，但车辆不在 Park 锁定状态。先锁定 Park，再重新执行：

```text
ENABLE_OTA
```

### OTA 上传失败

先确认窗口仍打开：

```text
OTA_STATUS
```

如果 `window=0`，重新执行：

```text
ENABLE_OTA
```

然后在 120 秒内上传。若 Arduino CLI 不能识别网络端口，先记录为 OTA 工具链问题；无线串口本身可按 TCP/Web Console 验收。
