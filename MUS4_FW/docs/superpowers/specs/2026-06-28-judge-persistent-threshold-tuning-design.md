# Judge 持久化评分阈值入口设计

## 背景

当前 `/judge` 已经完成第一阶段的最小可用实现：

- 通过现有 WebSocket 遥测作为主通路获取 `latest` 与增量点。
- 在页面内完成 `pseudoSpeed` 监控、`gyroZ` 曲线、实时总分、6 个维度评分和碰撞扣分。
- 通过 HTTP `/api/data?since=...` 作为 WebSocket 断连后的兜底链路。

这使得 `/judge` 已经可以作为“监控优先的评分页”使用，但当前评分阈值仍然存在两个明显问题：

- 所有评分阈值都写死在页面脚本中，只适合开发时快速试验。
- 实车调参结果无法持久化，设备重启后会丢失。

用户已经明确确认：

- 下一阶段优先做“实车调参入口”。
- 第一批持久化参数仅限评分阈值。
- 持久化位置选择设备侧 `NVS/Preferences`。
- 第一批参数集合限定为：
  - `collisionThreshold`
  - `bigTurnThreshold`
  - `windowSize`

因此，本轮目标不是做一个大而全的调参台，而是为 `/judge` 增加一个最小闭环的、可持久化的评分阈值入口。

## 目标

- 为 `/judge` 新增一个“评分阈值调参入口”。
- 第一批仅支持 `collisionThreshold`、`bigTurnThreshold`、`windowSize` 三个参数。
- 配置保存到设备侧 `NVS/Preferences`，设备重启后仍然保留。
- 保存后新参数立即作用于后续评分计算，无需设备重启。
- 页面提供“读取当前配置”“保存配置”“恢复默认值”三项能力。

## 非目标

- 不在本轮加入串口命令调参入口。
- 不在本轮加入浏览器本地覆盖配置。
- 不在本轮加入 6 个评分维度的权重或内部系数持久化。
- 不在本轮加入 `pseudoSpeed` 生成参数的持久化调参。
- 不在本轮加入多套配置档位或配置切换预设。
- 不在本轮新增独立调参页面，仍然以内嵌在 `/judge` 内的方式实现。

## 方案对比

### 方案 1：`/judge` 页面 + HTTP 配置接口 + NVS 持久化

- 在固件中增加一组 Judge 配置结构与 NVS 读写逻辑。
- 在 `WebConsoleServer` 中增加读取、保存、恢复默认值接口。
- 在 `/judge` 页里增加一个可折叠的调参区域。

这是本轮推荐方案。

优点：

- 最贴合用户当前目标。
- 与现有 `runtimeState.prefs` / `mus4Prefs` 模式保持一致。
- 页面调试与设备配置形成闭环，使用成本最低。

缺点：

- 需要同时改动固件配置逻辑和 Web 页面。
- 保存逻辑、校验逻辑和页面同步逻辑都要补齐。

### 方案 2：页面调参 + 串口命令双入口

- 在方案 1 基础上再加一组串口命令。
- 支持网页和串口同时修改 Judge 配置。

优点：

- 对没有浏览器环境的调试也更方便。
- 后续自动化调参脚本更容易接入。

缺点：

- 本轮范围明显扩大。
- 会把命令系统、权限反馈和帮助文案一并卷进来。

### 方案 3：浏览器本地缓存 + 手动同步

- 参数只保存在浏览器端。
- 页面刷新后还能继续使用，但设备重启或更换浏览器就丢失。

优点：

- 实现快。
- 不需要改固件配置存储层。

缺点：

- 不满足“设备侧持久化”目标。
- 设备真实生效参数和浏览器显示参数可能分离。

## 最终决策

本轮采用方案 1：在固件中加入 Judge 阈值配置结构与 `Preferences` 持久化逻辑，并通过轻量 HTTP 接口让 `/judge` 页面完成读取、保存和恢复默认值。

## 配置模型

### 配置结构

建议引入一个小而明确的 Judge 阈值配置结构，例如：

```cpp
struct JudgeConfig {
    float collisionThreshold;
    float bigTurnThreshold;
    uint8_t windowSize;
};
```

结构要求：

- 字段仅包含本轮确认的 3 个参数。
- 不提前引入与本轮无关的权重、预设、pseudoSpeed 参数等字段。
- 保持默认值清晰、可独立初始化。

### 运行时位置

Judge 配置应存放在设备侧运行时状态中，便于：

- Web 接口读取当前值。
- 页面保存后立即作用于后续评分逻辑。
- 后续如需扩展其它入口，也能复用同一份配置。

推荐方式：

- 将其挂接到现有 Wi-Fi / Web 运行时状态附近。
- 若有必要，可新增一个小型 Judge 运行时对象，但不要为 3 个值引入过度抽象。

### 持久化位置

持久化统一复用现有 `runtimeState.prefs` / `mus4Prefs` 模式。

原则：

- 不创建第二套配置存储框架。
- Judge 阈值与现有 Wi-Fi / 校准配置共享同一个 `Preferences` 实例。
- 命名空间与键名保持短小、稳定、易迁移。

例如可采用一组独立键：

- `judge_col_th`
- `judge_turn_th`
- `judge_win_sz`

键名可在实现时微调，但必须保证：

- 不与现有配置键冲突。
- 含义明确。
- 后续版本可平滑兼容。

## 默认值与边界

### 1. `collisionThreshold`

作用：

- 比较相邻 `gyroZ` 样本突变量，判断是否触发碰撞提示与扣分。

默认值：

- 沿用当前页面实现中的可工作初值。

边界要求：

- 必须设定合理上下限。
- 下限不能小到让正常漂移动作被频繁误判为碰撞。
- 上限不能大到让碰撞检测形同虚设。

### 2. `bigTurnThreshold`

作用：

- 判断何时进入“大弯区”，驱动“大弯稳定”维度的计算逻辑。

默认值：

- 沿用当前实现中大弯阈值的可工作初值。

边界要求：

- 必须限制在安全范围内。
- 过小会让系统几乎始终处于大弯区。
- 过大则会让该维度长时间失效。

### 3. `windowSize`

作用：

- 控制评分窗口长度，用于滑动窗口内的稳定性、变化率与均值计算。

默认值：

- 沿用当前评分页中的窗口长度。

边界要求：

- 只允许在较小整数区间内变化。
- 不允许取 0、负数或明显过大的值。
- 该值既影响评分“手感”，也影响页面内的窗口统计行为。

## 生效策略

### 启动加载

设备启动时：

1. 先构造 Judge 默认配置。
2. 再从 `Preferences` 读取持久化值。
3. 若对应键不存在，则沿用默认值。
4. 若持久化值非法，则回退到默认值。

### 保存生效

当页面点击“保存”且固件校验通过后：

- 新配置立即写入运行时。
- 同时持久化到 `NVS/Preferences`。
- 后续新样本的评分逻辑立即使用新配置。

### 不回溯重算

保存后的新配置只影响保存之后的后续评分样本。

明确不做：

- 不回溯重算已经累计的旧样本。
- 不强制重置当前总分。

原因：

- 回溯重算会让页面逻辑复杂化。
- 调参时通常更符合直觉的是“从下一批样本开始看变化”。

### 恢复默认值

页面提供“恢复默认值”按钮，触发后：

- 固件把运行时 Judge 配置恢复为默认值。
- 同时写回 `Preferences`。
- 页面重新显示默认值。

## 接口设计

Judge 配置接口全部走现有 HTTP 路由体系，不通过 WebSocket 下发。

### 读取当前配置

提供一个读取当前 Judge 配置的接口，例如：

- `GET /api/judge-config`

返回内容至少包含：

- `collisionThreshold`
- `bigTurnThreshold`
- `windowSize`
- 默认值信息（可选，但推荐提供，便于页面恢复默认值和显示参考）

### 保存配置

提供一个保存 Judge 配置的接口，例如：

- `POST /api/judge-config`

提交内容包含：

- `collisionThreshold`
- `bigTurnThreshold`
- `windowSize`

行为：

- 先进行字段完整性和范围校验。
- 校验通过才写入运行时并持久化。
- 返回明确成功或失败结果。

### 恢复默认值

提供恢复默认值接口，例如：

- `POST /api/judge-config/reset`

行为：

- 固件恢复默认配置。
- 写回 `Preferences`。
- 返回当前默认值配置结果。

## 页面设计

### 页面位置

调参入口不新建独立页面，而是内嵌到现有 `/judge` 中。

设计原则：

- 仍保持 `/judge` 以监控和评分为主。
- 调参区域默认折叠或次级展示，避免压过主视觉。

### 页面内容

调参区域至少包含：

- `collisionThreshold` 输入项
- `bigTurnThreshold` 输入项
- `windowSize` 输入项
- “保存”按钮
- “恢复默认值”按钮
- 当前保存状态或错误提示

### 页面行为

进入 `/judge` 后：

1. 页面拉取当前 Judge 配置。
2. 将 3 个参数填充到表单。
3. 用户修改后点击“保存”。
4. 成功时提示已保存并立即生效。
5. 失败时显示错误原因，但不清空用户输入。

### 即时观测

调参入口应与当前评分页联动，让用户在保存后能继续直接观察：

- 碰撞触发是否变得更灵敏或更迟钝。
- 大弯区触发是否更合理。
- 窗口大小改变后评分条和总分变化是否更平滑。

## 校验与错误处理

### 固件侧校验

固件必须对提交值做最终校验，页面校验只能作为辅助。

最少包含：

- 字段完整性检查
- 数值类型检查
- 上下限检查
- `windowSize` 的整数性检查

### 错误返回

若提交数据非法：

- 固件拒绝写入运行时和 `Preferences`。
- 接口返回明确错误文本或结构化错误码。

页面收到错误后：

- 保留用户当前输入。
- 显示失败原因。
- 不覆盖成默认值。

## 成功标准

- `/judge` 页面能读取设备当前 Judge 阈值配置。
- 用户可修改 `collisionThreshold`、`bigTurnThreshold`、`windowSize` 并保存。
- 保存后设备无需重启，新配置立即作用于后续评分样本。
- 设备重启后配置仍保留。
- 点击“恢复默认值”后，配置回到默认状态并同步持久化。
- 非法输入不会污染运行时或 `Preferences` 中的配置。
