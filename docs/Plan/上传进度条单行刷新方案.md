# 上传进度条单行刷新优化方案

## 1. 背景与问题

### 1.1 现状
当前固件上传流程中，ESP32 Bootloader 会通过串口输出以 `=` 字符表示的上传进度，格式类似：
```
Writing at 0x00010000... (5 %)
Writing at 0x00020000... (10 %)
Writing at 0x00030000... (15 %)
...
```
或者是纯进度条格式：
```
[=====     ] 50%
[========  ] 80%
```

目前的处理方式是直接逐行打印到控制台，会产生大量连续的输出行，视觉效果杂乱，且无法直观看到实时进度。

### 1.2 优化目标
将上传进度以**单行刷新**的形式显示，效果如下：
```
⣾ 正在上传... [==========        ] 50%
```
随着进度更新，整行动态刷新，不会产生多行输出，上传完成后自动换行。

---

## 2. 实现方案

### 2.1 整体思路
1. **解析层**：在串口输出/命令输出中识别进度行，提取进度百分比和进度条文本
2. **渲染层**：复用现有 `Spinner` 动画机制，将进度信息追加到"正在上传..."提示右侧，通过 `\r` 回车符实现单行刷新
3. **兼容层**：非进度行的输出正常打印，不破坏原有日志；无法识别的进度输出回退到默认行为

### 2.2 核心改造点

#### 改造点 1：增强 `Spinner` 类，支持附加后缀文本
**文件**：`arduino-cli.py` → `Spinner` 类（第 72-105 行）

**修改内容**：
- 新增 `update_suffix(text)` 方法，允许外部动态设置进度后缀文本
- 在每次刷新动画时，将后缀文本拼接到提示信息后
- 格式：`{动画字符} {提示文本} {后缀文本}`

示例接口：
```python
spinner = Spinner("正在上传...")
spinner.start()
spinner.update_suffix("[=====     ] 50%")  # 实时更新进度后缀
spinner.stop()
```

#### 改造点 2：封装进度行解析工具函数
**文件**：`arduino-cli.py` 新增公共函数

**实现逻辑**：
```python
def parse_progress_line(line: str) -> Optional[str]:
    """
    解析串口输出中的进度行，返回格式化后的进度字符串
    无法识别则返回 None
    """
    # 匹配模式1: "(X %)" 格式，如 "(50 %)"
    match = re.search(r'\((\d+)\s*%\)', line)
    if match:
        percent = int(match.group(1))
        bar_length = 20
        filled = int(percent / 100 * bar_length)
        bar = "[" + "=" * filled + " " * (bar_length - filled) + "]"
        return f"{bar} {percent}%"

    # 匹配模式2: 已经是 [=====] XXX% 格式，直接返回美化后的版本
    match = re.search(r'\[=+\s*\]\s*\d+\s*%', line)
    if match:
        return match.group(0)

    return None
```

#### 改造点 3：改造 `run_command()` 函数，处理实时输出
**文件**：`arduino-cli.py` → `run_command()` 函数（第 553-612 行）

**修改内容**：
- 在逐行读取子进程输出时，对每一行调用 `parse_progress_line()`
- 如果识别为进度行：
  - 调用 `spinner.update_suffix()` 更新进度后缀
  - 不直接打印该行
- 如果不是进度行：
  - 先输出一个换行，结束当前进度行的刷新状态
  - 正常打印该行内容
- 命令执行结束后，停止 Spinner 并换行，恢复终端状态

**边界处理**：
- 进度行和普通日志混合出现时，先换行再打印日志，避免覆盖
- 上传成功/失败的最终信息正常打印，不受影响
- 调试模式（`--verbose`）下关闭单行刷新，输出全部原始日志，便于排错

#### 改造点 4（可选）：串口监视器模式下的进度识别
**文件**：`arduino-cli.py` → `monitor()` 函数（第 799-867 行）

**说明**：
- 纯串口监视模式下，用户可能会看到设备重启时的上传进度
- 同样可以应用相同的解析逻辑，统一体验
- 但要注意不要误识别用户应用程序的输出，增加一个开关选项控制是否启用

## 3. 交互效果设计

### 3.1 正常流程（默认模式）
```
>>> 开始上传固件到 COM9...
⣾ 正在上传... [==========        ] 50%
```
整行刷新，进度从 0% 到 100% 平滑更新，上传完成后：
```
>>> 开始上传固件到 COM9...
✅ 上传完成，耗时 12.34s
```

### 3.2 有警告/错误输出的情况
如果上传过程中出现普通日志或警告：
```
>>> 开始上传固件到 COM9...
⣾ 正在上传... [=====          ] 30%
[WARN] 串口缓冲区溢出，正在重试...
⣯ 正在上传... [========       ] 60%
✅ 上传完成，耗时 15.21s
```
普通日志打断进度刷新，单独成行，进度条在新的一行继续刷新。

### 3.3 调试模式（`-v` / `--verbose`）
关闭单行刷新，输出全部原始日志，与现有行为完全一致，便于调试。

---

## 4. 兼容性与回退方案

1. **向后兼容**：不修改任何原有参数和调用方式，直接替换即可生效
2. **自动降级**：识别不出进度格式时，自动回退到逐行打印的原有行为，不会出现空白或乱码
3. **开关控制**：新增 `--no-progress` 参数，用户可以手动关闭单行刷新功能
4. **终端适配**：检测终端是否支持 ANSI 转义序列，不支持的环境（如部分 CI 日志系统）自动降级为逐行输出

---

## 5. 测试验证方案

| 测试场景 | 预期结果 |
|----------|----------|
| 正常上传完整流程 | 进度条从 0% 到 100% 平滑更新，最终显示成功提示，整个过程只有一行进度 |
| 上传过程中插入普通日志输出 | 日志单独成行显示，进度条在下一行继续刷新，不丢失信息 |
| 上传失败报错 | 错误信息完整打印，不被进度条覆盖 |
| 加上 `--verbose` 参数 | 关闭单行刷新，输出全部原始日志，与旧版行为一致 |
| 加上 `--no-progress` 参数 | 关闭单行刷新，逐行打印输出 |
| 重定向输出到文件（非 TTY） | 自动降级，不输出转义字符和刷新，文件内容干净 |
| 上传中断（Ctrl+C） | 正确恢复终端光标和换行状态，不破坏后续命令行显示 |

## 6. 实施步骤

### 阶段一：核心功能实现
1. 增强 `Spinner` 类，支持后缀文本更新
2. 实现 `parse_progress_line()` 解析函数
3. 改造 `run_command()` 函数，集成进度解析和单行刷新逻辑

### 阶段二：边界与兼容性处理
1. 实现终端 TTY 检测，非交互环境自动降级
2. 增加 `--no-progress` 参数开关
3. 处理异常退出（Ctrl+C、错误中断）时的终端状态恢复
4. 调试模式下自动关闭单行刷新

### 阶段三：测试与优化
1. 真实环境下测试上传流程，验证进度显示准确性
2. 测试各种异常场景（上传失败、中途中断、混合日志输出）
3. 性能验证：确保进度刷新不影响上传速度
